# 多优选订阅生成器并发容灾与聚合技术指南

## 1. 概述与设计背景

在原版的 **edgetunnel** 架构中，优选订阅生成器（`SUB` 字段）通常仅支持配置单一主机域名（如 `sub.example.com`）。在实际生产使用场景中，该模式存在明显的单点风险：
1. **单点故障 (SPOF)**：若配置的订阅生成器遭遇网络抖动、DNS 污染或服务器宕机，用户客户端将完全无法拉取最新订阅节点。
2. **生成器污染**：部分公开优选生成器域名（例如返回 Telegram 频道的 HTML 网页或伪装页）返回 200 状态码，若直接拼接其内容会导致大量 HTML 标签混入订阅，损坏 Clash / Sing-box / Surge 等客户端的配置解析。
3. **管理后台交互受限**：原管理后台仅提供单行输入框，无法便捷地可视化管理多个生成器源。

为了彻底解决以上问题，本项目引入了**多优选订阅生成器并发容灾拉取架构**与**前端动态卡片管理组件**。

---

## 2. 核心架构与技术实现

### 2.1 并发请求与单点超时熔断机制

核心实现在 [`_worker.js`](file:///E:/workspace/me/edgetunnel/_worker.js) 的 `获取单个优选订阅生成器数据` 与 `获取优选订阅生成器数据` 函数中：

- **多生成器解析**：支持数组、逗号分隔（`,`）或换行分隔（`\n`）的多域名配置，并自动清洗 `sub://` 前缀及非法空格。
- **并发拉取 (`Promise.allSettled`)**：多个生成器同时发起请求，避免串行网络耗时叠加。
- **4秒熔断机制 (`AbortController`)**：
  为每个外部生成器请求注入 `signal: controller.signal`。若单个生成器在 4 秒内未能建立连接或响应超时，触发中断，自动降级熔断，绝不影响其他正常生成器的拉取速度。

```javascript
const controller = new AbortController();
const timeoutId = setTimeout(() => controller.abort(), 4000);
const response = await fetch(优选订阅生成器URL, {
    headers: { 'User-Agent': 汇聚订阅_UA + ' Uid/0x' + uid + ' Version/' + EDT_版本号 },
    signal: controller.signal
});
clearTimeout(timeoutId);
```

### 2.2 防 HTML 污染与合法节点清洗

针对部分伪装或已失效但返回 200 网页的生成器（如返回 HTML 文档），系统执行了多重内容守卫：
1. **响应头与首字符判定**：若响应的 `Content-Type` 包含 `text/html`，或者正文原始文本以 `<` / `<!DOCTYPE` 开头，直接判定为非法订阅源并记录告警，立即跳过。
2. **Base64 解码二次校验**：对于 Base64 编码的响应，解码后再次验证是否为网页源代码。
3. **协议严格过滤**：在提取其它协议节点（如 `vmess://`、`vless://`、`trojan://`、`ss://`）时，通过正则表达式严格匹配协议格式，绝不将非协议行或 HTML 残留标签塞入最终订阅。

### 2.3 节点去重与聚合合并

聚合逻辑采用 `Set` 集合数据结构：
- 所有成功返回的生成器，其优选 IP 节点（`IP:Port#备注`）与三方节点（`协议://...`）会被自动合并并进行全局去重。
- 若所有配置的生成器均因网络超时或故障无法拉取，系统会友好返回携带明确错误信息的占位节点，便于用户快速排障。

## 3. 管理后台前端动态 UI 增强

为了在无需重新打包和部署远端 Pages 静态资源的前提下支持动态交互，在 Worker 代理 `/admin` 流量时实现了 [`增强管理后台HTML`](file:///E:/workspace/me/edgetunnel/_worker.js) 动态注入：

1. **DOM 结构自动重构**：
   - 将原单行 `<input id="generatorURL">` 输入框隐藏为底层数据桥梁。
   - 在其原位置动态插入卡片容器 `#generatorListContainer`、输入项列表与 **`+ 添加生成器`** 按钮。
2. **双向数据绑定与劫持**：
   - 前端每一行拥有独立的输入框与 **`删除`** 按钮。
   - 用户添加、修改或删除输入框时，会自动把各生成器域名以逗号序列化，回写至底层的 `generatorURL.value`。
   - 通过 `Object.defineProperty` 拦截底层 `generatorURL.value` 的 setter，当后台初始化或执行 `renderConfig()` 渲染配置时，自动反序列化并动态渲染回多输入框。
   - 原生的 `saveConfig()` 函数无需做任何改动即可无缝读取并保存多生成器配置到 KV 中。
